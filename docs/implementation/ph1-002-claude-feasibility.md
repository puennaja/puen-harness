## ผลเตรียมการและขอบเขตหลักฐาน

**DOCUMENTED** หมายถึงพบข้อความใน primary documentation ไม่ใช่ผล native; **PROPOSED** หมายถึงแนวทางหรือการทดลองที่ยังรออนุมัติ; **UNKNOWN/BLOCKED** หมายถึงยังขาดหลักฐานหรือสิทธิ์ Native outcome ของทุกกรณีด้านล่างคือ **NOT RUN** ไม่ใช้คำว่า supported/passed จากเอกสาร และไม่ใช้ผล mock แทนพฤติกรรมจริง

## Candidate interface และหลักฐานเอกสาร

### C1 — Claude Code structured headless

**DOCUMENTED:** CLI reference ระบุ `-p`, `--input-format stream-json`, `--output-format stream-json`, `--verbose`, `--include-partial-messages`, `--model`, `--max-turns`, `--max-budget-usd`, `--no-session-persistence`; `--tools` จำกัด built-in tools แต่ไม่จำกัด MCP; `--allowedTools` เป็น auto-approval rules; `--strict-mcp-config` จำกัด MCP sources; `--permission-prompt-tool` ใช้ MCP host รับ permission prompts การรองรับต้องผูกกับ exact version ([CLI reference](https://code.claude.com/docs/en/cli-reference))

**PROPOSED:** เปรียบเทียบ text input สำหรับ tool-less identity smoke กับ bidirectional stream-json สำหรับ permissions/cancellation โดยเลือกเพียงหนึ่ง transport ต่อ approved experiment ตรวจ frame types, terminal result, stdout/stderr separation, bounded buffering และการปิด stdin ไม่ทำ terminal-screen scraping หรือเดา undocumented control packets การสร้าง permission MCP host เป็น code change ที่ยังต้องอนุมัติ และ host ที่อนุมัติต้องเป็นส่วนควบคุมของ harness ไม่เปิดเครื่องมือของ server ให้โมเดลใช้อย่างกว้าง

### C2 — Claude Agent SDK for TypeScript

**DOCUMENTED:** `@anthropic-ai/claude-agent-sdk` ฝัง native Claude Code agent loop ผ่าน binary; ต่างจาก `@anthropic-ai/sdk` Messages client ซึ่งเป็น direct API และไม่ได้ทดแทน native loop ตาม ADR การเสนอ claude.ai login/rate limits เป็นส่วนของ third-party product ต้องได้รับ prior approval ตามข้อจำกัดที่หน้า overview ระบุ จึงยังสรุปไม่ได้ว่า subscription product integration ได้รับอนุญาตสำหรับ intended use นี้แล้ว ([Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview))

**DOCUMENTED:** `query({ prompt, options })` รับ `AsyncIterable<SDKUserMessage>` สำหรับ streaming input; รองรับการ interrupt/permission interaction ต่างจาก single-message mode ที่มีข้อจำกัด mid-session control ([Streaming Input](https://code.claude.com/docs/en/agent-sdk/streaming-vs-single-mode)) การเปิด partial events ใช้ `includePartialMessages: true` แล้วอ่าน `stream_event`; final `result` ต้องแยกจาก text deltas ([Streaming output](https://code.claude.com/docs/en/agent-sdk/streaming-output))

**PROPOSED:** ตรวจ public option/method signatures ของ exact pinned release ก่อนสร้าง runner ได้แก่ `cwd`, `model`, `tools`, `allowedTools`, `disallowedTools`, `permissionMode`, `canUseTool`, `settingSources`, `env`, `mcpServers`, `hooks`, `maxTurns`, `maxBudgetUsd`, `persistSession`, `includePartialMessages`, `abortController` และ `Query.interrupt()`/การปิด Query ไม่ถือว่าทุกชื่อ/behavior ผ่านเพียงเพราะมีในเอกสารอ้างอิง ต้องยืนยัน packaged declaration และ bundled CLI ที่ถูกใช้จริง

ข้อจำกัดการค้นคว้า: [full TypeScript reference](https://code.claude.com/docs/en/agent-sdk/typescript) โหลดผ่าน web reader ไม่สำเร็จเพราะหน้าใหญ่เกิน จึงใช้ official conceptual pages ที่อ้างรายข้อข้างต้น ไม่ใช้ mirror หรือ declaration ของแพ็กเกจคนอื่นเป็นข้อยืนยัน โดยเฉพาะ exact shutdown API, options ที่ไม่มีรายละเอียดในหน้าที่อ่าน และ protocol version ยัง **UNKNOWN** การตรวจ declaration ภายหลังต้องมีสิทธิ์อ่าน package metadata/source หรือดาวน์โหลดที่ระบุไว้ก่อน

### Stop, retry และ cost ที่ต้องกำหนดก่อน first live cohort

เอกสาร headless อธิบาย `SIGINT`/SDK `interrupt()` เพื่อจบ turn และ `SIGTERM` ที่อาจไม่มี final result แต่เรียก `SessionEnd`; มี `system/api_retry` และบาง auth-helper retries ไม่ส่ง event ช่วงแรก ([Headless lifecycle/retries](https://code.claude.com/docs/en/headless)) จึงต้องทดสอบ process ownership, no-new-work หลัง cancel และ uncertain usage แทนตีความ exit code ว่า complete

**PROPOSED:** first cohort ไม่มี spike-driver/harness retry หรือ second invocation; native internal retries ต้อง characterize และ bound เท่าที่ exact release รองรับ เช่น candidate `CLAUDE_CODE_MAX_RETRIES=0` และ documented `CLAUDE_CODE_NONSTREAMING_TIMEOUT_RETRIES=0` พร้อมไม่ inherit watchdog ยังไม่อ้างว่า `MAX_RETRIES=0` ครอบคลุมทุก cause จนพิสูจน์ได้ หนึ่ง invocation ไม่เท่ากับหนึ่ง model/API request ความไม่แน่นอนต้องปรากฏใน time/attempt/cost consent ก่อนรัน ไม่เพิ่มข้อบังคับใหม่ว่าต้องปิด native retries ทุกชนิดได้จึงทดสอบได้ แต่ห้ามรันเกิน permit หรือสรุปว่ามี strict request/financial ceiling

ปิด unapproved hooks/plugins/MCP/skills/memory/agents/workflows/remote control/background features และไม่ใช้ `--add-dir`; tool-less cohort ใช้ empty built-in tools และ deny MCP แยก ส่วน coding-readonly cohort ต้องตรวจ Read/path policy ก่อนเปิดอย่างน้อยหนึ่ง file tool ไม่มี Bash ใน initial text-only smoke การปิด `Agent` ไม่เพียงพอถ้า Bash ยังเริ่ม background process ได้ ต้องครอบ input `run_in_background`, shell fan-out และ inherited extensions ตามจริงด้วย
